# 시나리오 설계 원칙

이 문서는 돌발 사건 시나리오를 작성할 때 지켜야 할 기준을 정의한다.
개별 사건과 체인 설계 모두 이 원칙에서 벗어나지 않도록 한다.

---

## 1. 사건은 창작 루프에 실질적인 영향을 줘야 한다

- 단순 텍스트 팝업으로 끝나는 이벤트는 설계하지 않는다
- 모든 사건은 창작 계획(파트 분배, 포메이션, 출시 시점 등)에 변경 압박을 가해야 한다
- 플레이어가 사건 후 "무언가를 다시 결정해야 하는 상황"에 처하도록 설계한다

---

## 2. 징조-사건-결과는 하나의 체인으로 연결된다

각 사건은 독립된 이벤트가 아니라 **3단 구조**로 이루어진다.

```
징조 (조기 신호)
  │
  ├─ [개입 성공] → 사건 예방 또는 강도 약화
  └─ [무시 / 포착 실패] → 사건 발생
                              │
                              ├─ [적절한 대응] → 피해 경감 후 창작 복귀
                              └─ [방치 / 오판] → 추가 사건 또는 멤버 이탈
```

- 징조는 항상 구체적인 묘사로 표현된다 (수치 직접 노출 금지)
- 결과는 단일 결말이 아닌 플레이어 선택에 따른 분기로 설계한다

---

## 3. 사건은 페널티만이 아니다

- 악재 사건과 호재 사건이 모두 존재한다
- 호재 사건도 창작 계획 재조정을 요구한다 (예: 갑작스러운 기회로 일정 앞당기기)
- 사건의 목적은 플레이어를 처벌하는 것이 아니라 **판단을 유발**하는 것이다

---

## 4. 사건은 멤버를 입체적으로 드러내야 한다

- 사건은 해당 멤버의 **성격 특성(트레이트)**과 연결되어 발생 가능성이 결정된다
- 같은 상황에서도 트레이트에 따라 반응 방식이 달라야 한다
- 예: "파트 배정 불만" 사건은 **반항기** 특성 보유 멤버에게 더 높은 확률로 발생한다

---

## 5. 완벽한 예방은 불가능하도록 설계한다

- 징조를 포착하고 상담을 실시해도 **일정 확률**로 사건이 발생한다
- 이야기꾼이 징조 없이 직접 사건을 발생시킬 수 있다
- 플레이어가 항상 긴장감을 유지하도록 불확실성이 남아야 한다

---

## 6. 이야기꾼 성향에 따라 사건 풀을 차등 적용한다

| 이야기꾼 | 사건 풀 적용 방식 |
|----------|-------------------|
| 매니저 지망생 | 전체 사건 풀에서 강도 "약~중" 사건 위주로 선택. 루프당 1~2회 |
| 타블로이드 기자 | 갈등·루머·스캔들 계열 사건 비중 증가. 루프당 3~5회 |
| 업계 베테랑 | 강도 "강" 사건 위주. 빈도는 낮지만 파급력이 크다. 루프당 0~1회 |

---

## 7. 사건 작성 항목 기준

각 사건은 아래 항목을 모두 갖춰야 한다.

| 항목 | 설명 |
|------|------|
| 사건 ID | 고유 식별자 (예: EVT-M-001) |
| 사건명 | 짧고 명확한 이름 |
| 발생 PHASE | 어느 창작 루프 단계에서 발생하는가 |
| 발생 조건 | 트리거 조건 (수치 조건 또는 특성 조건) |
| 강도 | 약 / 중 / 강 |
| 유형 | 멘탈 / 갈등 / 이탈 / 루머 / 외부변수 / 호재 |
| 징조 묘사 | 사건 전 플레이어에게 노출되는 신호 텍스트 |
| 사건 묘사 | 사건 발생 시 출력되는 텍스트 |
| 대응 선택지 | 플레이어가 선택할 수 있는 행동 목록 |
| 분기 결과 | 각 선택지에 따른 결과 (수치 영향 포함) |
